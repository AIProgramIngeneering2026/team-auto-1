# Сервис для массовых рассылок уведомлений

## Проблема
При рассылке большого количества уведомлений одновременно может возникнуть ряд проблем: уведомления должны быть персонализированы; если генерировать и отправлять уведомления одновременно, база данных компании может не выдержать нагрузки; необходимо обойти блокировку спам-фильтром провайдера.

## Для кого
Разработчики и команды компаний, которым нужно рассылать уведомления клиентам по нескольким каналам (email, Telegram, webhook) и не реализовывать в каждом проекте отправку, повторы и контроль статуса.
Получатели уведомлений: клиенты этих компаний.

## Что входит в систему:
1. Движок планирования и сегментации, который умеет запускать рассылку в строго заданное время (например, в субботу в 10:00) или не отправлять в ночное время и делить получателей на группы.
2. Подстановка персональных данных получателя в шаблон сообщения.
3. Ограничитель трафика, который будет подстраиваться под лимиты внешних провайдеров.
4.  Отправка по каналам email, Telegram, webhook с ограниченными повторами; статус каждого уведомления (принято, отправляется, доставлено, не доставлено, отменено) и отмена до начала отправки.

## Что не входит в систему:
1. Конструктор писем, который бы предоставлял визуальный редактор блоков для создания писем.
2. Управление подписками: формы подписки обрабатываются внешними CRM-системами.
3. Валидация базы почт: Проверка базы на существование ящиков перед рассылкой — задача внешних специализированных утилит.
4. Интерфейс, реальные ключи провайдеров и реальные персональные данные: при разработке каналы заменяются тестовой заглушкой.
5. Сегментация получателей и аналитика открытий и кликов: не входят в первую версию.
