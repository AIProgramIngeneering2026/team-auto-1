# Contributing

## 1. Работа с ветками

Основная ветка проекта — `main`. В неё напрямую не коммитим.

Для каждой задачи создаём отдельную ветку от актуальной `main`.

Формат названий веток:

- `feature/<name>` — новая функциональность.
- `fix/<name>` — исправление ошибки.
- `docs/<name>` — документация.
- `test/<name>` — тесты.
- `ci/<name>` — CI/CD и инфраструктура.

Примеры:
- `docs/contributing`
- `feature/send-notification`
- `fix/invalid-request`
- `ci/github-actions`

Названия веток пишем на английском языке, в kebab-case.

## 2. Коммиты

Используем формат:

`<type>: <short description>`

Типы коммитов:
- `feat` — новая функциональность.
- `fix` — исправление ошибки.
- `docs` — изменения документации.
- `test` — добавление или изменение тестов.
- `ci` — изменения CI/CD.
- `refactor` — рефакторинг.
- `chore` — технические изменения.

Примеры:
- `docs: add contributing guidelines`
- `feat: implement notification sending`
- `fix: validate notification request`
- `ci: add build workflow`

Описание коммита должно быть коротким и отражать суть изменений.

## 3. Pull Requests и Code Review

Все изменения в `main` вносятся через Pull Request.

Правила:
1. Один Pull Request должен решать одну задачу или логически связанную группу задач.
2. В описании PR указываем, что было сделано, и ссылку на соответствующий Issue.
3. Каждый PR должен получить review минимум от одного другого участника команды.
4. Автор PR учитывает замечания и вносит необходимые исправления.
5. Review должен проверять корректность реализации, соответствие задаче, читаемость кода и отсутствие очевидных ошибок.
6. После одобрения PR может быть влит в `main`.

Автор PR не должен самостоятельно подтверждать собственные изменения.

## 4. Definition of Done

Задача считается выполненной, если:

- Реализация соответствует требованиям задачи.
- Изменения находятся в отдельной ветке.
- Создан Pull Request.
- Получено минимум одно одобрение Code Review.
- Все существенные замечания по review обработаны.
- Проверки CI завершились успешно (если применимо).
- Ссылки на связанные Issues и документацию проверены.
- Pull Request влит в `main`.
